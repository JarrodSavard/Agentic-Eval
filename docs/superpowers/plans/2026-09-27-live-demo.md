# Local live demonstrations implementation plan

> Execute inline with superpowers:executing-plans and test-driven development, preserving the user's selected local execution/public recording approach.

**Goal:** Demonstrate genuine model actions as they happen and publish their recorded evidence.
**Architecture:** Existing runner emits observable events; a loopback Python service manages one bounded invocation; the Nuxt live page polls typed progress and reuses state/replay components.
**Stack:** Python, FastAPI/Uvicorn, Pydantic; existing Nuxt, TypeScript, pytest, Vitest and Playwright.
**Spec:** ../specs/2026-09-27-live-demo-design.md

## Constraints and review focus

- No API keys in browser responses, public files or logs; reject foreign origins/hosts and unauthenticated mutations.
- One active invocation, no request retries, shared $0.50 default / $1 maximum, existing turn/tool/token limits.
- Stop during an in-flight response must preserve accounted usage and forbid subsequent actions.
- A disconnected page must not restart a run; refresh reconnects to the current/latest invocation.
- Missing keys, stale pricing, invalid selections and unexpected provider failure must produce clear states and preserve recorded evidence.

## Delivery

1. Runner: failing tests for ordered immutable event delivery and cancellation before generation/tool side effects; implement optional callbacks without changing offline artifact output.
2. Local service: failing API/service tests for boundaries, selection, concurrency, progress and artifacts; implement typed run requests/status, one worker and local static serving. Generate live TypeScript from its Pydantic schema.
3. Viewer: failing browser tests for local setup, start, progress, fault display, stop, completed comparison and download; implement the Live route and one-command local launch. Reuse the current visual system.
4. Release: full offline suite, generated-contract checks, production build and byte budget; fresh review of material changes; genuine capped run when keys are ready, verify and publish the entire invocation; push source and recordings, verify Pages.
