## What we measure

Independent deterministic checks cover final outcomes, tool arguments, observable workflow, recovery, authorization/safety, structured reporting, and execution efficiency. Each check includes a pass/fail/not-applicable/not-assessed verdict, an explanation, and trace references. There is no opaque combined quality score. A guarded unsafe attempt is different from an actual harmful state change. A valid alternative booking or safe retry is accepted.

Expand the catalog to 48 cases: the existing three failure families plus misleading instructions in tool data, no suitable car, and competing customer needs. Each family has four clean/challenge pairs. The reference policy must pass every solvable task and correctly report unavailable rentals. Deliberately faulty policies and corrupted evidence must fail relevant checks. Original task definitions remain replayable.

Add a structured `report_result` tool containing booked request/car/date triples and unavailable request IDs. Independently compare this receipt with the saved state; do not pretend deterministic receipt checks judge arbitrary prose. Older recordings without this tool show reporting as not assessed.

Repeated-trial summaries group only matching model/provider/settings/scenario/version/source. Show sample sizes, single-run success, pass@k and pass^k for supported k using finite-sample combinatorial estimators; insufficient data stays unknown. Incomplete trials stay in attempt counts. Never pool scripted policies with real models. Compare saved baselines by matching cases/configurations, explicitly distinguishing harness regression tests from new live model evidence.
