# Road Test

## Audience and job

Software engineering hiring teams inspect a working portfolio application and its public source. They need to understand how agent reliability is measured, inspect evidence, and assess engineering judgment quickly.

## Product truth

A fictional rental desk provides 24 deterministic scenarios: twelve tasks paired with clean/fault variants. Model trials are stochastic. Scripted demonstrations are not evidence of model performance. Genuine runs are small illustrative samples, never a model ranking.

## Platform and stack

Web, responsive and keyboard accessible. Nuxt/TypeScript viewer; local Python runner with a loopback-only live interface; versioned JSON boundary. No hosted model execution, database, or user accounts. GitHub Pages publishes recorded evidence. The user chose local live execution and shareable real recordings on September 27, 2026.

## Confirmed constraints

Test-driven development. $0.50 default live budget, $1 maximum per invocation. Offline tests. Eight model turns, twelve tool calls, 512 output tokens and 6,000 input tokens per request. No automatic paid retries. Public source with copyright reserved.

## Design context

Approved direction: restrained rental booking board. The interface prioritizes readable comparisons, honest provenance, and keyboard-operable trace replay. This is an engineering portfolio, not a commercial car-rental product.

The user chose rental cars on September 27, 2026 to make the prompts, data and UI understandable to an everyday audience. Show the customer request first, then the problem, the AI’s actions and the actual booking. Keep the entire product focused on car rentals.
