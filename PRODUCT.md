# Observatory

## Audience and job

Software engineering hiring teams inspect a working portfolio application and its public source. They need to understand how agent reliability is measured, inspect evidence, and assess engineering judgment quickly.

## Product truth

A fictional observatory provides 24 deterministic scenarios: twelve tasks paired with clean/fault variants. Model trials are stochastic. Scripted demonstrations are not evidence of model performance. Genuine runs are small illustrative samples, never a model ranking.

## Platform and stack

Web, responsive and keyboard accessible. Nuxt/TypeScript static viewer; local Python runner; versioned JSON boundary. No hosted model execution, database, or user accounts. GitHub Pages deployment.

## Confirmed constraints

Test-driven development. $0.50 default live budget, $1 maximum per invocation. Offline tests. Eight model turns, twelve tool calls, 512 output tokens and 6,000 input tokens per request. No automatic paid retries. Public source with copyright reserved.

## Design context

Approved direction: restrained observatory instrument panel. The interface prioritizes readable comparisons, honest provenance, and keyboard-operable trace replay. This is an engineering portfolio, not a commercial observatory product.
